Conversational Hand Gestures

An inclusive communication bridge for children: a child raises an open palm, a cartoon face on screen greets them, and the two hold a short conversation, a game, a story, a goodbye — using only hand shapes. No network stack, no camera data ever leaves the device, so the conversation stays private to the child using it.

Demo

Watch it in action

The conversation, the rock-paper-scissors game, and the story generation, all running live on the EK-RA8P1 board.

The exchange is meant to mimic conversational reciprocity — the back-and-forth turn-taking of a real conversation — rather than a single command triggering a single response, with the animated face appearing to understand and talk back through its reactions.

The TRON × AI theme is about combining RTOS and AI rather than running one alongside the other. On µT-Kernel 3.0, this demo does exactly that: two independent AI workloads, computer vision and language generation, share a single Renesas RA8P1 chip through the kernel's own scheduling and memory primitives.

The Challenge

Competing for CPU time and limited memory

On a single microcontroller, combining two AI workloads is not automatic. AI workloads are large relative to an MCU's compute and memory budget, and running more than one at once — for example a vision pipeline that must keep up with a live camera while a language model computes in the background — puts them in direct competition for CPU time and for the limited fast memory an AI accelerator needs. Without guaranteed task order, a slower AI workload can stall a time-critical one.

System architecture

Two AI workloads, one chip

The vision half feeds an MIPI camera into a palm-detection model and a hand-landmark model, both running on the on-chip Ethos-U55 NPU; the resulting 21 joint positions become one of five named gestures through geometry ratio tests on the Cortex-M85. The language half runs a "Tiny" Llama2 model at 8-bit quantization that writes a short story one token at a time, reading its weights directly out of external Octo-SPI flash instead of copying them into RAM, with its int8 matrix multiplication calling the Cortex-M85's Helium vector instructions directly — sixteen int8 lanes per instruction instead of one.

Scheduling

Fixed priorities keep vision responsive

µT-Kernel's fixed task priorities let these two workloads share one chip safely, as four application tasks. Story generation only uses CPU time left over after the other three, so it cannot delay the camera or the display: the camera picture keeps updating and story text keeps appearing together, with no dropped frames on the panel.

Signaling

One event flag, single-writer memory

The same four tasks coordinate through a single µT-Kernel event flag plus shared, single-writer memory — a signaling path small enough that its worst-case timing is easy to reason about.

The event flag carries signals, not data

Only ready and done bits pass through it. An interrupt sets its bits directly, with nothing in between that could overflow.

tk_set_flg / tk_wai_flg · interrupt-safe

Data travels in single-writer structures

Processed images, joint positions, gesture results, and story text each live in a structure written by exactly one task, so no two tasks race over the same memory.

shared memory · one writer per structure

Closing Thought

A small proof of a larger idea

This demo is deliberately small — one board, one camera, one child-sized conversation. But the same properties that make it work reach well beyond this one demo. A gesture-only interface reaches people voice and touch assistants don't: non-verbal children, hospital patients, anyone across a language barrier — the back-and-forth reciprocity here is what makes an interface feel like it's listening, which matters most for the users existing assistants serve worst.

Keeping every byte on-device means that reach doesn't cost privacy: nothing about a child's face or voice has anywhere to leak, by construction, not by policy.

And underneath both is the same discipline TRON was built on since 1984: computers embedded everywhere, working reliably, disappearing into their environment. This demo puts that discipline under a new kind of pressure, without giving it up — two AI workloads sharing one RA8P1 chip, under µT-Kernel's fixed priorities, without ever missing a frame. AI doesn't have to mean flaky, cloud-dependent, unpredictable. Not when it inherits an RTOS's decades of determinism, instead of replacing it.
